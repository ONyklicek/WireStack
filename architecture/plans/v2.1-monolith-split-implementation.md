# V2.1 — Rozřezání monolitů: implementační plán

Rozpracování fáze **V2.1** z [`v2-master-plan.md`](v2-master-plan.md). Cíl:
`WithTable` → headless collaborators + tenký Livewire adapter (ADR 0017
invariant C), `Column` base zmenšit + specializované typy (invariant D). Bez
změny public API.

## 0a. Revize proti kódu (2026-08-26)

Plán je z 6. 7. Mezitím doběhla výkonnostní větev a V2.0, a obojí mu sáhlo přímo
do scope. Podklad: [`v2-audit-2026-08-26.md`](v2-audit-2026-08-26.md) §2.2, po
oponentuře.

### Co se změnilo v číslech

| Tvrzení plánu | Naměřeno 2026-08-26 |
|---|---|
| `WithTable` 3213 ř., 96 public metod | **2880 ř., 99 deklarací metod** |
| `Column` 1749 ř., 139 public metod | **1681 ř., 123 metod** |
| — | **`Table.php` 2935 ř. / 193 public metod** — v den psaní plánu měl 1616/131, tedy byl menší než `Column` i `WithTable`. Není to přehlédnutý monolit, je to nová položka |

Oponentura přitom zabila tvrzení, že se monolit „jen rozprostřel": extrakce
`169decb` byla coupling-neutrální a `WithTable` reálně zmenšila o 39 %. Dnešní
nárůst pochází z **nových odpovědností**, ne z redistribuce.

### Co je hotové jinde — půlka fáze A

`table/src/Support/` obsahuje `TableRenderPlan` + sedm slice-plánů
(`Column/Action/Layout/Paging/Interaction/Shell/RowRenderPlan`), `ColumnSet`,
`TableQueryState`, `RowRenderer`, `CardRenderer`, `SummaryRenderer`. Vzniklo to
pod [`livewire-4-migration-and-performance.md`](livewire-4-migration-and-performance.md),
ne pod V2, a plán o tom neví.

**Důsledek:** jména z §A.2 jsou dnes kolizní. `TableRenderState` by byl druhý
název pro `TableRenderPlan`. Nová jména se musí volit tak, aby se `*RenderPlan`
vyhnula.

**A pět tříd už headless je** — `ColumnSet`, `FilterControl`, `MobileCard`,
`TableGestures`, `TableShortcutLegend` (nula zmínek Livewire v testech).

### Co je hotové jinde — část fáze A přes V2.0

Čtení už kolaborantem prochází: `paginateQuery()`, nepaginovaná cesta i poll
token delegují na `DataSource`. `TableDataset` z §A.2 by tedy dnes obaloval něco,
co už vlastníka má.

### Co ve `WithTable` reálně zbývá

Chování, ne render. Naměřené shluky:

| Shluk | Metod | Příklady |
|---|---|---|
| query / read | 12 | `buildTableQuery`, `fetchTableRecords`, `executeWithCache`, `generateQueryCacheKey`, `queryCacheState`, `queryCacheScope` |
| polling / live | 6 | `computePollChecksum`, `shouldPoll`, `recordTableWrite`, `announceTableWrite`, `getTableLiveChannel` |
| render orchestrace | 4 | `tableRenderPlan`, `queueRowPartial`, `queueSatellitePartials`, `skipTableRender` |
| souhrny | ~6 | `computeTableSummaries`, `computeGroupSummaries`, `computeSubRowGrandTotals`, `buildSubRowGrandTotalQuery` |
| debug / introspekce | ~8 | `ddTableQuery`, `dumpTableColumns`, `getTableRawSql`, `getTableColumnsInfo` |
| zbytek | 77 | akce, modaly, inline edit, export/import, filtry, skupiny |

Partial/live vrstva (`queueChangedRowPartials`, `recordTableWrite`,
`announceTableWrite`, `getTableLiveChannel` + `Support/LiveChannel`) přišla
s výkonnostní větví a v plánu vůbec není.

### Co plán navíc nezná

- **Islands.** Datová oblast je `@island('data-region', always: true)` a
  editovatelné buňky ji cílí jménem.

  **DoD 2 render větve — částečně splněno 2026-08-26.** Chyběl host kontrakt, ne
  vůle: render vrstva brala hostitele jako `mixed` a slice plán si od něj
  vyžádal `isColumnVisible()`, takže se nedal obsloužit doublem. Vznikly tři —
  `Contracts\{ShowsTableColumns, ExpandsTableRows, SummarisesTable}` — a
  kartová větev `TablePartials` je od té chvíle testovatelná bez Livewire
  komponenty; předtím nešla dosáhnout vůbec.

  Parametry zůstávají `mixed` **záměrně**: `WithTable` je trait a nemůže
  `implements`, takže zúžení typů by po každé konzumentské komponentě chtělo
  `implements` navíc — BC break kvůli vnitřní čistotě. Kontrakt nese *tvar*,
  který hostitel musí umět odpovědět, a je to tvar, který si test postaví.
  Zbytek (`ShellRenderPlan`, `InteractionRenderPlan`) čeká na stejné ošetření —
  polling, live kanál, readiness a přístup ke stavu.
- **ADR 0025.** `ModuleLayersTest` hlídá vrstvy uvnitř core a **vyhodí výjimku
  na neznámý top-level modul**. Nový adresář v core je tedy první commit fáze,
  ne poslední.
- **Brány.** §Testovací strategie nejmenuje `composer coverage:verify` (diff
  gate pokrývá každý přidaný i změněný řádek) ani `npm run verify:drivers`, což
  je jediná kontrola nad Alpine/Livewire chováním.
- **Druhá rodina filtrových views** — inline `Filter::inlineView()` se sedmi
  šablonami v `tables/columns/partials/filter-*.blade.php`, vedle panelové
  `filterView()`.

### Co ve `WithTable` doopravdy je (změřeno 2026-08-26)

Než se cokoli přesune, tohle mění zadání fáze A:

| | |
|---|---|
| metod | **99** — z toho **65 public**, 34 protected/private |
| metod do 5 řádků | **20** (82 ř. dohromady) |
| řádků v tělech metod | **1905** z 2880 |
| metod nad 40 řádků | **12 — a drží 703 ř., tedy 37 % veškerého kódu v tělech** |

Dvanáct největších: `mountWithTable` 110 · `updateTableCell` 73 ·
`queueChangedRowPartials` 67 · `buildTableQuery` 62 · `updatedTableState` 59 ·
`resolveTableSummaries` 54 · `submitHaltModal` 52 · `getTableRecords` 48 ·
`queueSatellitePartials` 46 · `validateTableCell` 46 ·
`buildSubRowGrandTotalQuery` 44 · `getGroupRecords` 42.

**Monolit není tenká delegační vrstva.** Hypotéza, že `WithTable` je hlavně API
plocha, se testovala a padla: jen pětina metod je kratší než pět řádků. Je to
skutečná logika, a je koncentrovaná.

**Ale 65 public metod se přesunout nedá.** Jsou to Livewire endpointy a veřejné
API: `updateTableCell` volá Alpine jako `$wire.updateTableCell(…)`
(`verify-cell-island.mjs:9`, `verify-editable-per-page.mjs:114`), `submitHaltModal`
je `wire:submit` v `halt-modal.blade.php`, `queryCacheScope` je zdokumentovaný
override hook. Livewire vyžaduje, aby metoda byla na komponentě.

**Fáze A tedy nemůže znít "rozřezat `WithTable` na kolaboranty".** Endpointy
zůstávají; co se stěhuje, jsou **těla**. Cíl je tenký endpoint, který zavolá
vlastníka — přesně to, co `computePollChecksum()` a `paginateQuery()` udělaly ve
V2.0 a co `AI_CODING_STANDARD.md` § Adapters předepisuje.

Cílový seznam je proto těch dvanáct metod, ne 99, a metrikou úspěchu je **řádků
v tělech**, ne počet metod ani řádků souboru. Několik z nich už má vlastníka
vedle sebe: `CellEditPipeline` pro `updateTableCell`/`validateTableCell`,
`SummaryRenderer`/`SummaryBatch` pro souhrny, `RowRenderer` pro partial cestu.

### Opravené pořadí — a proč „nejlevnější první" nefunguje

Shluky změřené na řádky, ne odhadem:

| Shluk | Metod | Řádků | Poznámka |
|---|---|---|---|
| query cache | 5 | **60** | z toho `generateQueryCacheKey` 1 ř. (deleguje) a `queryCacheScope` 1 ř. — **zdokumentovaný override hook** |
| debug / introspekce | 10 | **80** | `TableIntrospector` + `HasSqlDebug` už existují |
| souhrny | 6 | **114** | `SummaryRenderer` + `SummaryBatch` už existují |
| polling / live | 7 | **127** | `computePollChecksum` už deleguje na `DataSource` |
| **zbytek** | **~71** | **~2500** | akce, modaly, inline edit, export/import, filtry, skupiny |

**Čtyři „levné" shluky jsou dohromady 381 řádků z 2880 — 13 %.** Monolit v nich
nebydlí.

A query cache je z nich nejhorší první krok, ne nejlepší: `generateQueryCacheKey`
je jednořádková delegace, `queryCacheScope` je override hook, jehož docblock
volajícího výslovně zve („Override to widen or narrow it — a tenant id, a parent
record"). Extrakce by odebrala rozšiřovací bod a nezmenšila skoro nic.

**Pořadí tedy:**

1. **Debug / introspekce** (80 ř.) — jediný shluk, který je čistý přesun bez
   návrhového rozhodnutí a bez rizika pro chování. Vlastníci existují.
2. **Souhrny** (114 ř.) — logika, ne hooky; `SummaryRenderer` je vedle.
3. **Akce / modaly / inline edit** (~2500 ř.) — **tady je fáze A**. Vlastní
   rozpočet, vlastní golden-master sada, koordinace se zbytkem V2.0.b (149
   signatur `Model $record`).
4. **Polling / live a query cache** — až nakonec, nebo vůbec. Obojí už z velké
   části deleguje a zbytek jsou override hooky, které jsou veřejnou plochou.

Bod 3 není „poslední, protože je velký". Je to celá fáze; body 1–2 jsou úklid,
který jí nepředchází ani ji neusnadňuje. Kdo chce V2.1 odhadnout, ať odhaduje
bod 3.

Fáze B (Column) revizí nedotčena: `StatusColumn`, `MoneyColumn`, `RelationColumn`
a `MetricColumn` dál chybí, ověřeno.

## A. Rozřezání `WithTable` na headless collaborators

### A.1 Současný stav

`WithTable` je Livewire trait mixující 96 public metod a ~15 dalších traitů
(`TableQueryService`, `HasGrouping`, `HasSubRows`, `HasSummary`, `HasResponsive`,
`HasView`, `WithTableQueryString`, forms `InteractsWith*`). Traity **nejsou
headless** — sahají na `$this->tableState`, `$this->dispatch()`, Livewire
lifecycle. 435 takových couplingů.

### A.2 Cílové collaborators (plain PHP, testovatelné bez Livewire)

Dle ADR 0017 invariant C (dataset · state · selection/bulk · render · Livewire adapter):

| Collaborator | Vlastní | Pohltí z WithTable | Vazba na jinou fázi |
|---|---|---|---|
| **`TableDataset`** | query build + paginate + cache + change-token | `TableQueryService`, `paginateQuery`, `executeWithCache`, `generateQueryCacheKey`, `get/count` | **sem přistane V2.0 `DataSource`** |
| **`TableSelection`** | výběr řádků + resolve bulk/single record | `toggleRecordSelection`, `selectAllRecords`, `getSelectedRecords`, resolve `find/whereIn` | **sem přistane V2.0.b `RecordContract`** |
| **`TableActionRunner`** | action pipeline (table/bulk/header/confirmed) + modal flow | `executeTableAction*`, `executeBulkAction*`, `executeHeaderAction*`, `executeConfirmedAction` | delegace na core `ActionPipeline` |
| **`TableRenderState`** | render-data (rows→viewdata, viditelnost sloupců, sub-rows, summary, flatten, expansion) | `HasSubRows`, `HasSummary`, `HasGrouping` render části, `toggleColumn`, `toggleRowExpansion`, `toggleFlattenMode` | — |
| **`WithTable` (adapter)** | Livewire lifecycle + `tableState` (serialized) + delegace | `mount*`, `updated*`, `render`, polling, thin wrappery public metod | drží Livewire coupling |

**Vzor:** strangler-fig. Public API `WithTable` (96 metod) zůstává **beze změny** —
tělo se přesune do collaboratoru, metoda se stane tenkou delegací. Každá extrakce
je samostatně zelená.

### A.3 Pořadí extrakce (nízké riziko → vyšší)

| Krok | Collaborator | Proč pořadí | Odhad |
|---|---|---|---|
| A-1 | `TableDataset` | nejčistší seam (query už je v `TableQueryService`); **nosič V2.0.a** | 3–4 d |
| A-2 | `TableSelection` | malý, izolovaný; **nosič V2.0.b `RecordContract`** | 2 d |
| A-3 | `TableRenderState` | střední; render-data bez side-effectů | 3 d |
| A-4 | `TableActionRunner` | největší blast radius (modal flow, forms integrace) — až po ustálení | 4 d |
| A-5 | `WithTable` adapter dočistit | tenký lifecycle + delegace; smazat pohlcené traity | 2 d |

**Coupling strategie:** collaborator dostane stav přes konstruktor/DTO
(`TableStateView` read-model nad `tableState`), **nesahá** na Livewire `$this`.
Side-effekty (dispatch, notifikace) vrací jako výsledek/`ActionResult`, adapter je
provede. Tím se collaborator testuje bez Livewire lifecyclu (ADR 0017 exit).

### A.4 PHPStan gotcha (kritické)

`WithTable` je dnes analyzovaný **jen jako trait** (konkrétní hosti jsou v
`excludePaths`, viz `RelationManager` gotcha [[filament_parity]]). Nové
collaborators jsou **konkrétní třídy** → PHPStan je bude analyzovat naostro. To je
**žádoucí** (proto extrakce), ale: collaborators nesmí dědit Livewire magii →
musí být čisté PHP, jinak explodují stejně jako `WithTable`. Toto je hlavní důvod,
proč jsou headless.

## B. Zmenšení `Column` base + specializované typy

### B.1 Současný stav

`Column` (1749 ř., 139 public metod) extends `DataComponent`, deleguje design
concerns do Foundation traitů. **Není** to duplicitní god-object — ale base pořád
absorbuje surface-specific chování, které dle invariant D patří do typů.
Specializované typy dnes: Text/Badge/Boolean/Icon/Image/Select/Toggle/Button
(474 ř.)/Poll (630 ř.)/Stacked (385 ř.)/Split/TextInput (823 ř.). **Chybí** cílové
ERP typy: `MoneyColumn`, `StatusColumn`, `RelationColumn`, `MetricColumn`.

### B.2 Práce

| Krok | Obsah | Odhad |
|---|---|---|
| B-1 | **Audit 139 metod base**: rozdělit na *cross-cutting* (identity, visibility, capabilities, state format, view resolve — zůstává) vs *surface-specific* (patří do typu). Výstup: seznam metod k přesunu. | 1 d |
| B-2 | `StatusColumn extends BadgeColumn` (ADR 0018 — enum status → barva/ikona přes `Enum\HasColor/HasLabel/HasIcon`) | 1 d |
| B-3 | `MoneyColumn` (měna/formát/lokalizace nad `FormatsState`) | 1 d |
| B-4 | `RelationColumn` (auto eager-load relace; konsoliduje dnešní `->relationship()` roztroušené v base) | 1–2 d |
| B-5 | `MetricColumn` (agregace/sparkline nad existující summary infrastrukturou) | 1 d |
| B-6 | Přesun surface metod z base do typů + `@deprecated` na base variantách (odstranění 3.0) | 2 d |

**BC:** `Column::make()` a všechny stávající typy fungují beze změny; nové typy
jsou aditivní; přesuny z base jsou deprecation-first (base metoda deleguje na typ
přes shim celý 2.x).

## C. Reziduum #5/#6 (mimo hlavní práci)

- **Modal:** ověřit, že `action-modal`/`halt-modal` partial nemají žádnou zbytkovou
  bespoke modal logiku mimo `<x-wire-modals::*>`; pokud ano, doladit. **Jinak
  nedělat nic** — je hotové. (½ d ověření.)
- **Filtry:** `SelectFilter` (searchable dropdown) a `TernaryFilter` mají
  oprávněně custom view. Rozhodnutí: **nechat custom**, zdokumentovat proč (ne
  každý filtr je form-field). (½ d docs.)

### Milníky & kritická cesta

```
V2.0.a hotové ──► M1: TableDataset zelený (A-1)  ← V2.0 read-cesta zapojena
                     │  stávající table suite beze změny
                     ▼
              M2: TableSelection + RecordContract (A-2) ← V2.0.b zde
                     │
                     ▼
              M3: TableRenderState (A-3) ──┐
                     │                     ├─► M4: TableActionRunner (A-4) — nejtěžší
                     ▼                     │
              (paralelně B: Column) ───────┘
                     │
                     ▼
              M5: WithTable = tenký adapter (A-5) + Column typy → V2.1 DONE
```

- **M1 = go/no-go**: `TableDataset` zelený a **celá table suite beze změny** =
  důkaz, že extrakce nezměnila chování. Pokud vyžaduje úpravy testů, seam je
  špatný → zastavit.
- **M4 = nejtěžší** (`TableActionRunner`: modal flow + forms integrace) — kritická
  cesta A větve.
- **B (Column) neblokuje A** — běží paralelně, sjednotí se v M5.

## Testovací strategie

- **Golden master pro chování:** před extrakcí zafixovat stávající table feature
  suite jako referenční; po každé extrakci **musí zůstat zelená beze změny** (to je
  primární BC důkaz — stejný princip jako V2.0 M1).
- **Nové unit testy per collaborator:** `TableDataset`/`TableSelection`/
  `TableRenderState`/`TableActionRunner` testovatelné **bez** Livewire (headless
  exit kritérium). Shape coverage: prázdný dataset, cursor/simple paging, bulk
  napříč stránkami, sub-row/flatten/expansion kombinace.
- **Column typy:** unit per nový typ (Status/Money/Relation/Metric) + LSP kontrola
  (pozor na historické `ImageColumn::size()` LSP fatal [[column_partial_migration]]).
- **Matrix:** `composer test:table` + `test:sortable` (sortable staví na table);
  `Integration` (runtime/state/modal flow); `analyse` + `lint`; benchmark bez regrese.

| Riziko | Mitigace |

| V2.0.b × A-2 dvojitá práce | A-2 **je** nosič V2.0.b — dělat jednou (viz depends_on) |

## Definition of done (celé V2.1)

1. `WithTable` public API beze změny; tělo v collaborators; adapter tenký
   (cíl: výrazně pod 3213 ř., orchestrace v collaborators).
2. Collaborators testovatelné bez Livewire lifecyclu (headless exit, ADR 0017 C).
3. `Column` base zmenšen; `StatusColumn`/`MoneyColumn`/`RelationColumn`/
   `MetricColumn` existují, plně otestované; přesuny z base deprecation-first.
4. Golden-master table suite zelená beze změny; `analyse`/`lint` čisté; benchmark
   bez regrese.
5. V2.0.b (`RecordContract`) realizováno uvnitř A-2 (ne dvakrát).
6. Docs (`architecture/table.md` — nová collaborator struktura) + boost sync.
7. `v2-master-plan.md` V2.1 exit odškrtnut; #5/#6 označeny hotové; V2.3 odblokováno.
