## S1 — Redukce `app()`/`new` v execution seamech (ADR 0017 gap #6)

### Cíl
Execution třídy nesmí v hot path samy vytvářet závislosti (`new Dehydrator(...)`,
`app(PluginManager::class)`) — snižuje to testovatelnou izolaci a přenositelnost
(ADR 0017 invariant „runtime seams explicitní"). Závislosti se injektují.

### Práce
| Krok | Soubor | Změna |
|---|---|---|
| S1-1 | `SaveHandler.php` (`new`×6: Dehydrator/ValueTransformer/CastResolver/RelationshipSaveHandler…; `app()`×8) | závislosti přes konstruktor/factory; `PluginManager` přes injektovaný resolver (ne `app()->bound()` v hot path) |
| S1-2 | `core/Actions/ActionPipeline.php` (`new`×4) | stage instance přes injektovaný seznam/factory |
| S1-3 | `forms` runtime factory | jedno místo, kde se poskládá `SaveHandler` s deps (service provider binding) |
| S1-4 | *table strana* (`TableQueryService`, `WithTable`) | **NE zde — řeší V2.1** collaborator konstruktory (poznámka do V2.1 §A.3) |

**Vzor:** default hodnoty v konstruktoru zachovat (`__construct(?Dehydrator $d = null)`
→ fallback na `new` jednou v konstruktoru, ne v hot metodě) → **BC-safe**, žádná
změna call-site, jen testy můžou injektovat mock.

**Cache seam pattern:** `app()->bound(PluginManager::class)` opakovaně v hot path
→ resolvnout jednou (memoized property/konstruktor), viz už doporučeno ve
v2-deferred #7 rizicích.

## S2 — Typed contracts/hooks primární; deprecovat array-hook duplicitu (invariant H)

### Cíl
Dnes běží na každém lifecycle bodě **oba** — `runHook(array)` i `runTypedHook(DTO)`.
To je dvojí průchod a dvě API pro totéž. Invariant H: **typed primární**, generic
array hook jen pro legacy/edge integrace.

### Práce
| Krok | Soubor | Změna |
|---|---|---|
| S2-1 | `PluginManager.php` | `runHook(array)` → `@deprecated`; typed payload je kanonický. Interně: pokud existují jen typed listenery, array dispatch přeskočit |
| S2-2 | `TableQueryService.php` (91/100, 189/229, 296/302), `SaveHandler.php` (55/62, 92/97) | odstranit **dvojí** dispatch — volat jen `runTypedHook`; array `runHook` volat jen když jsou registrovaní array-listeneři (BC bridge) |
| S2-3 | docs `docs/core/plugins.md` + boost guidelines | typed hook = doporučená cesta; array hook = legacy |

**BC:** array `runHook` API zůstává funkční celý 2.x (deprecation-first);
existující array-listener pluginy běží dál přes bridge. Odstranění dvojího
dispatche je interní optimalizace, ne BC break.

**Pozn.:** tohle **není** rušení hook systému (ADR 0014 hooks zůstávají pro
integrace/edge). Jen se typed varianta stává primární a ruší se redundantní
paralelní běh obou na hot path.

## S3 — Konsolidace hydration seamů (drobné, ověřovací)

### Cíl
Hydration je zapojená na více místech (`FormRuntime`, `Field`, `SaveHandler`
Dehydrator, `StateManager` enum-normalizace). Ověřit, že spolu netvoří mezery
(typová hydrace vs enum-normalizace vs dehydrace) a že je jeden kanonický owner
directionu request→typed→persist.

### Práce
| Krok | Obsah | Odhad |
|---|---|---|
| S3-1 | Audit: zmapovat všechny hydration/dehydration call-sites (`StateHydrator`, `Dehydrator`, `normaliseEnums`, `CastResolver`) do jednoho diagramu směru dat | ½ d |
| S3-2 | Pokud audit najde mezeru (typ nehydratovaný před validací apod.) → doplnit; jinak jen zdokumentovat kanonický tok | ½–1 d |

**Pozn.:** S3 může skončit „žádná změna, jen docs" — je to verifikační krok, ne
předjímaný refaktor. Nezvětšovat scope bez nálezu.

## Roadmap (sekvence / závislost / riziko / odhad)

| Krok | Obsah | Závislost | Riziko | Odhad |
|---|---|---|---|---|
| **S1** | app()/new redukce (forms/core; table ⟶ V2.1) | — (paralelní s V2.1) | nízké (BC-safe DI) | 2–3 d |
| **S2** | typed hooks primární, deprecovat array duplicitu | — | nízké–stř. | 2 d |
| **S3** | hydration seam audit + případný fix | — | nízké | 1–1½ d |

**Celkem ~5–6 dní** — nejmenší z architektonických fází, protože #2/#3/#4 jsou
hotové. Vše paralelizovatelné (různé soubory), žádná vnitřní závislost.

### Milníky
```
S1 ──► M1: SaveHandler/ActionPipeline bez app()/new v hot path (injektované deps)
S2 ──► M2: jediný typed dispatch na lifecycle bodech; array hook @deprecated bridge
S3 ──► M3: hydration tok zdokumentovaný (kanonický owner); případný fix → V2.2 DONE
```
Žádná kritická cesta mezi kroky — tři nezávislé, malé pracovní balíky.

## Testovací strategie

- **S1:** unit testy injektují mock deps (dřív nešlo — to je hlavní přínos);
  existující forms/core suite zelená beze změny (BC důkaz DI s default fallbackem).
- **S2:** typed hook round-trip (už pokryto); nový test — array-only listener
  pořád dostane dispatch (bridge), typed-only nespustí array cestu.
- **S3:** pokud fix → shape coverage nové hydration cesty; jinak jen docs.
- **Matrix:** `composer test:forms` + `test:core` + `test:table`; `Integration`
  (plugin dispatch, save lifecycle); `analyse` + `lint`; benchmark bez regrese
  (S1 nesmí přidat overhead — deps se resolví jednou v konstruktoru).

## Rizika & mitigace

| Riziko | Mitigace |
|---|---|
| DI přidá overhead do hot path | deps resolvnout **v konstruktoru** (jednou), ne v hot metodě; default `new` fallback |
| Dvojí→jediný dispatch rozbije array-listener plugin | BC bridge: array `runHook` běží když existují array-listeneři; deprecation-first |
| Překryv table app()/new s V2.1 → dvojí práce | S1 cílí forms/core; table stranu odškrtne V2.1 (koordinovat) |
| S3 scope creep | S3 je verifikace; refaktor jen při konkrétním nálezu, jinak docs-only |

## Definition of done

1. `SaveHandler`/`ActionPipeline` nevytváří závislosti v hot path (injektované,
   default fallback v konstruktoru); testy je můžou mockovat.
2. Na lifecycle bodech běží **jediný** (typed) dispatch; `runHook(array)`
   `@deprecated` s BC bridgem pro array-listenery; docs + boost aktualizované.
3. Hydration tok zdokumentovaný s kanonickým ownerem; případná mezera zavřená.
4. Forms/core/table suite zelená beze změny; `analyse`/`lint` čisté; bez perf regrese.
5. `v2-master-plan.md` V2.2 exit odškrtnut; #2/#3/#4 označeny hotové; table-strana
   S1 delegována do V2.1.
