# V2.0 — DataSource kontrakt: implementační plán

Rozpracování fáze **V2.0** z [`v2-master-plan.md`](v2-master-plan.md) podle
[ADR 0019](../decisions/0019-data-source-contract.md). Cíl: odemknout read-cestu
z tvrdé vazby na `Illuminate\…\Builder` na kontrakt `DataSource`, aniž se změní
chování Eloquent cesty.

**Vstupní brána:** ADR 0019 přijaté (ACCEPTED); V2.0 běží **před** V2.1
(rozřezání `WithTable`) — ale record-resolution seam (V2.0.b) se blast-radiusem
překrývá s V2.1, viz sekce Sekvence.

---

## 1. Mapa seamů (ověřeno v kódu 2026-07-06)

> **⚠️ Čísla řádků jsou zastaralá (přeměřeno 2026-08-26).** `WithTable` mezi tím
> spadl z 3213 na 2855 řádků, protože render-engine práce z
> [`livewire-4-migration-and-performance.md`](livewire-4-migration-and-performance.md)
> vytáhla resolvery do `table/src/Support/`. Seamy jako **kategorie** platí dál;
> konkrétní `soubor:řádek` níže **znovu odvoď**, než se jich dotkneš.

Read-cesta = tři kategorie terminální konzumace `Builder`u. Všechny musí projít
přes `DataSource`.

### A. Query building (vstup)
| Seam | Soubor | Dnes |
|---|---|---|
| base query | `Table::getQuery(): Builder` | `Table.php:233` (model/query/modifyQueryCallback) |
| setter | `Table::query(Builder)` | `Table.php:256` |
| plan+execute | `TableQueryService::buildQuery(Builder,…): Builder` | `TableQueryService.php:71` |
| execute | `QueryExecutor::execute(Builder,QueryPlan,?search): Builder` | `QueryExecutor.php:46` |
| pipes | `QueryPipe::handle(Builder,QueryPlan,Closure): Builder` | 8 default pipes |

### B. List / pagination (hlavní dataset)
| Seam | Soubor:řádek | Poznámka |
|---|---|---|
| paginator switch | `WithTable.php:628 paginateQuery()` | `simple/cursor/default` → Laravel paginators |
| cache wrapper | `WithTable.php:645 executeWithCache()` | `Cache::remember` nad paginate/get |
| unpaginated | `WithTable.php:614, 662, 1053` | `$query->get()` |
| group ordering | `WithTable.php:3203`, `Table.php:456` | druhý `buildQuery()` caller |

### C. Count / change-detection
| Seam | Soubor:řádek | Poznámka |
|---|---|---|
| total | `WithTable.php:1395` | `$query->count()` |
| rollup | `WithTable.php:1386` | `$record->getRelation($rel)->count()` |
| **change token 🔴** | `WithTable.php:448 generateQueryCacheKey()` | `getQuery()->getGrammar()->wrap()` + `toBase()->selectRaw("COUNT(*), MAX(updated_at)")` — **deep SQL coupling** |

### D. Record resolution (akce, selection, bulk)
| Seam | Soubor:řádek | Tvar |
|---|---|---|
| single | `WithTable.php:2106, 2935` | `getQuery()->find($key)` |
| single (first) | `WithTable.php:2054, 2339, 2404` | `where(pk,$key)->first()` |
| bulk/selection | `WithTable.php:1922/1947, 2209, 2380` | `whereIn(pk,$keys)->get()` |
| sub-row relation 🔴 | `WithTable.php:1665` | `getQuery()->getModel()->{$rel}()` — **Eloquent relation** |

**🔴 Tvrdé body (nejdou triviálně abstrahovat):**
1. `generateQueryCacheKey()` (448) — change-detection přes raw SQL grammar +
   `MAX(updated_at)`. Non-Eloquent zdroj tohle neumí → kontrakt dostane opt-in
   `changeToken(): ?string`; když vrátí `null`, polling change-detection se pro
   ten zdroj vypne (ne špatný výsledek).
2. Sub-row relation (1665) a rollup count (1386) — čistě Eloquent relace.
   → `DataSourceCapabilities::supportsSubRows()`; non-Eloquent zdroj sub-rows
   nenabídne (capability gate, ne tichý fail).

## 2. Cílové kontrakty (finální návrh; řeší open questions ADR 0019)

> **Rozhodnuto 2026-08-26 (vlastník repa), po [auditu](v2-audit-2026-08-26.md) §2.1.**
>
> **Neprůhledná část dotazu → capability degradace.** `buildQuery()` po
> `execute()` pokračuje sedmi kroky, které `QueryPlan` nepopisuje. Dva z nich —
> explicitní eager loads (`TableQueryService.php:285-287`) a `AggregateSubqueries`
> (`:293`) — se **přesunou do `QueryPlan`**, pole i pipes na ně už existují.
> Zbytek (uživatelské sort/filter closures typované `Builder`,
> `Column::applyFilter()`, `StableOrder`, sub-row presence subquery, hook
> `table.queried`) zůstává v `EloquentDataSource` a **non-Eloquent zdroj ho
> nedostane** — deklaruje, co umí, a nedeklarovaný aspekt v plánu vyhodí
> `UnsupportedQueryAspectException`. Eloquent cesta beze změny chování.
>
> **Collection zdroj: ano, ale ve .c — a fake zdroj hned v .a.** Klauzule
> `QueryPlan`u jsou plně deklarativní (`FilterClause`/`SortClause`/`SearchClause`
> nesou sloupec, operátor a hodnotu, žádné closures), takže je Collection splnit
> umí a práce je ohraničená. Osy, na kterých se liší, sedí 1:1 na capability,
> které už v enumu jsou: `sqlExpression` → `SqlExpression`, relační filtr/sort →
> `Joinable`, agregace přes subquery → `Aggregateable`, sub-rows → `SubRows`.
>
> Plný `CollectionDataSource` zůstává ve .c podle plánu — stavět druhý zdroj
> dřív, než je Eloquent cesta prokazatelně beze změny, znamená ladit dvě věci
> naráz. Ale **už v .a musí být v testech minimální fake zdroj**, který schválně
> nedeklaruje `Sortable`, a jím připnutá degradace. Interface s jediným
> implementátorem se vždycky svezne do tvaru toho implementátora; tohle je
> nejlevnější pojistka proti tomu.
>
> Do docs pak patří, že tabulka nad Collection je **omezená tabulka**: kdo napsal
> `->sortUsing(fn (Builder $q) => …)` nebo má relační sloupec, dostane výjimku.
> To je politika fungující správně, ale je to vlastnost, ne překvapení.

> **V2.0.b se dělí.** Resolution seam (`find`/`where->first`/`whereIn->get`,
> ~10 míst) jde do V2.0.b nad `RecordContract`. Akční a render call-sity —
> `Model $record` v signaturách, celkem **149 výskytů v 54 souborech** napříč
> core, table i sortable — jdou do V2.1 spolu s extrakcí chování. Odhad „2 dny"
> u b4 platil pro číslo, které audit vyvrátil.

Namespace `NyonCode\WireCore\Core\Data`.

```php
interface DataSource
{
    /** Hlavní dataset — vrací Laravel paginator (items = RecordContract). */
    public function paginate(QueryPlan $plan, PagingRequest $paging): Paginator;

    /** Nepaginovaný dataset (export, „vše"). */
    public function get(QueryPlan $plan): Collection;      // Collection<RecordContract>

    public function count(QueryPlan $plan): int;

    public function resolveRecord(int|string $key): ?RecordContract;

    /** @param array<int, int|string> $keys */
    public function resolveRecords(array $keys): Collection; // bulk/selection

    public function capabilities(): DataSourceCapabilities;

    /** Opt-in change token pro polling; null = change-detection vypnuto. */
    public function changeToken(QueryPlan $plan): ?string;
}

interface RecordContract
{
    public function getKey(): int|string;
    public function get(string $path): mixed;   // dot-path (atributy i relace)
    public function toArray(): array;
    public function unwrap(): mixed;             // úniková klapka na nativní objekt
}
```

**Rozhodnutí (locking ADR 0019 open questions):**

- **Q1 (Model vs wrapper):** `EloquentRecord` **wrapper** (ne editace frameworkové
  `Model`). Wrapping je líné a jen na record-resolution/render seamu; list-render
  cesta v V2.0.a zůstává na nativních Modelech (viz fázování) → nulová alokační
  regrese na hot listu. `unwrap()` vrací původní `Model` pro kód, který ho ještě
  potřebuje.
- **Paginator tvar:** `paginate()` vrací **Laravel paginator kontrakt**
  (`Illuminate\Contracts\Pagination\{LengthAwarePaginator,Paginator,CursorPaginator}`),
  ne vlastní `DataResult` — views a `paginateQuery()` konzumují paginator beze
  změny. Non-Eloquent zdroj si `LengthAwarePaginator` sestaví ručně. (ADR 0019
  sketch `DataResult` **zamítnut** ve prospěch menšího blast radiusu.)
- **Q3 (paging):** `PagingRequest { mode: simple|cursor|length_aware, perPage, page|cursor }`
  — pokrývá dnešní `paginateQuery()` switch (628) od začátku.
- **Q2 (metadata non-Eloquent):** mimo scope V2.0 — non-Eloquent zdroj deklaruje
  capabilities explicitně; metadata auto-resolve řeší V2.2 (v2-deferred #2).
- **Q4 (export/import):** export přepnout na `DataSource::get()` v **V2.0.c**
  (dnes streamuje z filtered query); import zůstává mimo (write-side).

**Capabilities — oprava návrhu (2026-08-26).** Původní `DataSourceCapabilities`
se **zamítá**. `Core/Capabilities/{Capability,CapabilitySet}` mezitím vznikly a
jsou kanonickým slovníkem schopností v celém repu — čte je `QueryPlanner`
(`:142`, `:265`) i `Column` (`:396`, `:413-417`), `DataComponent` je nese.
Druhý slovník pro tentýž pojem je přesně to, co `CLAUDE.md` § Architectural
Invariants zakazuje.

```php
public function capabilities(): CapabilitySet;
```

Enum `Capability` se rozšíří o čtyři případy, které dnes nemá a data source je
potřebuje: `Joinable`, `Paginable`, `SubRows`, `ChangeToken`. `Searchable`,
`Sortable`, `Filterable` a `Aggregateable` už existují.

**Degradace:** engine ctí jen aspekty, které zdroj v `capabilities()` hlásí;
nepodporovaný aspekt v `QueryPlan`u → `UnsupportedQueryAspect` (hlasitě), nikdy
tichý špatný výsledek (ADR 0019).

## 3. Work breakdown & roadmap

### V2.0.a — Kontrakt + `EloquentDataSource` (aditivní, chování beze změny)

**Cíl:** `TableQueryService`/`WithTable` teče interně přes `DataSource`, ale
`Table::getQuery(): Builder` a nativní Model rows fungují jak dnes.

| Krok | Soubor | Změna |
|---|---|---|
| a1 | `core/src/Core/Data/DataSource.php` | NOVÝ kontrakt |
| a2 | `core/src/Core/Data/DataSourceCapabilities.php`, `PagingRequest.php`, `Exceptions/UnsupportedQueryAspect.php` | NOVÉ hodnotové objekty |
| a3 | `core/src/Core/Data/EloquentDataSource.php` | NOVÝ default — obaluje `Builder`, deleguje na `QueryExecutor` + `paginateQuery` logiku; `changeToken()` = dnešní `generateQueryCacheKey` SQL |
| a4 | `table/src/Table.php` | `dataSource(DataSource)` + `getDataSource(): DataSource` (implicit `EloquentDataSource` z `getQuery()`); `getQuery()` **zůstává** (`@deprecated` až v .c) |
| a5 | `table/src/Services/TableQueryService.php` | `buildQuery()` interně staví `QueryPlan` a předá `EloquentDataSource` (Builder cesta beze změny) |
| a6 | `table/src/Concerns/WithTable.php:614-664` | `paginateQuery`/`executeWithCache`/`get` volají `getDataSource()->paginate/get`; paginator kontrakt beze změny |

**Testy:** `EloquentDataSourceTest` (paginate/get/count/changeToken parity vůči
dnešku), round-trip `QueryPlan` → výsledek; **všechny stávající table testy
zelené beze změny**. Benchmark: `EloquentDataSource` je tenký pass-through.
**Exit:** default cesta byte-for-byte jako V1; `Table::dataSource()` existuje.

### V2.0.b — `RecordContract` na resolution/action seamu

**Cíl:** akce/selection/bulk přestanou vyžadovat `Model`.

| Krok | Soubor | Změna |
|---|---|---|
| b1 | `core/src/Core/Data/RecordContract.php`, `EloquentRecord.php` | NOVÝ kontrakt + wrapper (`unwrap()`→Model) |
| b2 | `WithTable.php:2054,2106,2339,2404,2935` | `resolveRecord()` místo `find/where->first` |
| b3 | `WithTable.php:1922,2209,2380` | `resolveRecords($keys)` místo `whereIn->get` |
| b4 | akční render call-sites (`Model $record` → `RecordContract`) | signatury na kontrakt; `EloquentRecord::unwrap()` pro kód, co ještě chce Model |

**⚠️ Blast radius:** překrývá se s V2.1 (WithTable split). Koordinovat: b2–b4
dělat **spolu s** V2.1 collaborator extrakcí, ne dvakrát. Viz Sekvence.

**Testy:** `EloquentRecordTest` (getKey/get dot-path/toArray/unwrap); akční feature
testy zelené s `RecordContract`. **Exit:** akce/bulk běží nad `RecordContract`;
Model wrapper drží BC.

### V2.0.c — Public API + non-Eloquent referenční zdroj + deprecations

| Krok | Soubor | Změna |
|---|---|---|
| c1 | `core/src/Core/Data/ArrayDataSource.php` (nebo `CollectionDataSource`) | NOVÝ referenční non-Eloquent zdroj — dokazuje seam; deklaruje omezené capabilities |
| c2 | `table/src/Export/TableExport.php` | streamovat z `DataSource::get()` (Q4) |
| c3 | `Table::getQuery(): Builder`, `query(Builder)`, `QueryExecutor::execute(Builder)` | `@deprecated` (odstranění 3.0); shim přesměruje na `EloquentDataSource` |
| c4 | docs `docs/table/data-sources.md` + `architecture/table.md` + boost `DescribeTable`/guidelines | dokumentace seamu |

**Testy:** `ArrayDataSourceTest` — tabulka běží nad `Collection` (filter/sort/
search v mezích capabilities; nepodporovaný aspekt → `UnsupportedQueryAspect`).
**Exit:** tabulka prokazatelně běží nad non-Eloquent zdrojem; export přes
`DataSource`; deprecation warnings na místě; docs + boost sync.

### Roadmap (sekvence / závislost / riziko / odhad)

| Sub-fáze | Obsah | Závislost | Riziko | BC | Odhad |
|---|---|---|---|---|---|
| **V2.0.a** | kontrakt + `EloquentDataSource` + list/count cesta | ADR 0019 ACCEPTED | střední (hot files) | aditivní, chování beze změny | 2–3 d |
| **V2.0.b** | `RecordContract` na akcích/bulk | .a; **koord. s V2.1** | vysoké (blast radius) | Model wrapper BC | 2 d *(uvnitř V2.1)* |
| **V2.0.c** | non-Eloquent zdroj + export + deprecations + docs | .a, .b | nízké | deprecation-first | 1–2 d |

**Celkem ~5–7 dní čistého času** (bez V2.1 overheadu; .b se realizuje uvnitř V2.1
extrakce, takže její 2 dny se částečně překryjí s prací na collaborators).

### Milníky & kritická cesta

```
ADR 0019 ACCEPTED ──► M1: EloquentDataSource zelený (V2.0.a)
   (gate)                  │  stávající table suite beze změny = BC důkaz
                           ▼
                    ┌─ V2.1 start (rozřezání WithTable)
                    └─ M2: RecordContract na akcích (V2.0.b, uvnitř V2.1)
                           │
                           ▼
                    M3: non-Eloquent tabulka běží + export přes DataSource (V2.0.c)
                           │
                           ▼
                    M4: deprecations + docs + boost sync → V2.0 DONE
```

- **M1 — proof of no-regression** (konec .a): default Eloquent cesta byte-for-byte;
  celá stávající table suite zelená beze změny. Toto je go/no-go bod — pokud M1
  vyžaduje úpravy existujících testů, kontrakt je špatně navržený, zastavit a
  přehodnotit `EloquentDataSource` pass-through.
- **M2 — record abstrakce** (konec .b): akce/bulk nad `RecordContract`; realizuje
  se **uvnitř** V2.1, ne jako samostatný průchod WithTable.
- **M3 — seam proof** (konec .c): referenční `ArrayDataSource` prokáže odemčení;
  export teče přes `DataSource::get()`.
- **M4 — uzávěrka**: `@deprecated` shimy, docs, boost guidelines; ADR 0019 exit.

**Kritická cesta = M1**. Zbytek je nízkorizikový; M1 rozhoduje, jestli je návrh
kontraktu správný (nulová regrese na hot listu + zelená suite bez úprav).

## 4. Sekvence vůči V2.1 (kritické)

- **V2.0.a** je bezpečné **před** V2.1 (jen list/count/query cesta).
- **V2.0.b** (RecordContract na ~10 call-sitech ve `WithTable`) se překrývá
  s rozřezáním `WithTable` (V2.1). **Doporučení:** udělat V2.0.a → začít V2.1
  (headless selection/query collaborators) → V2.0.b **uvnitř** té extrakce, aby
  se ~10 call-sitů nešahalo dvakrát. `v2-master-plan.md` V2.1 exit tím dostane
  přidruženou závislost — poznamenat tam.
- **V2.0.c** až po ustálení .a/.b.

## 5. Testovací strategie (repo politika 100% nového kódu)

- **Unit:** každý nový kontrakt/VO/zdroj (`EloquentDataSource`, `EloquentRecord`,
  `ArrayDataSource`, `DataSourceCapabilities`, `PagingRequest`, exception).
  Shape coverage — ne jen happy path: prázdný plán, cursor vs simple vs length-aware,
  nepodporovaný aspekt, `changeToken()==null`.
- **Feature/Integration:** existující table suite musí zůstat zelená **beze změny**
  v .a (to je hlavní BC důkaz); nové feature testy pro `RecordContract` akce (.b)
  a non-Eloquent tabulku (.c).
- **Benchmark:** `TableBenchmarkTest` — `EloquentDataSource` nesmí regresovat
  (pozor: benchmark testy padají pod `--coverage`, viz [[filament_parity]] gotcha).
- **Matrix:** `composer test:table` + `test:core` + `test:forms`; `Integration`
  testsuite (runtime/state); `analyse` + `lint` čisté.

## 6. Rizika & mitigace

| Riziko | Mitigace |
|---|---|
| Perf regrese na hot listu z indirekce | `EloquentDataSource` tenký pass-through; list rows nativní Model do .b; benchmark před/po |
| Blast radius RecordContract × V2.1 | koordinovat .b uvnitř V2.1 extrakce (sekce 4) |
| Change-detection (448) u non-Eloquent | `changeToken(): ?string`; null → polling change-detection off, ne špatný výsledek |
| Sub-rows/rollup (1386/1665) u non-Eloquent | `capabilities()->supportsSubRows()` gate; jinak `UnsupportedQueryAspect` |
| `Builder` leaky v public signaturách | každou `@deprecated` + shim, ne rename (odstranění 3.0) |
| Tiché špatné výsledky u degradace | povinné `UnsupportedQueryAspect`, nikdy silent |

## 7. Definition of done (celé V2.0)

1. `DataSource` + `RecordContract` + `EloquentDataSource`/`EloquentRecord` +
   `ArrayDataSource` existují, plně otestované (100% nového kódu, shape coverage).
2. Default (Eloquent) cesta byte-for-byte jako V1 — stávající suite zelená beze změny.
3. Tabulka prokazatelně běží nad non-Eloquent zdrojem (referenční test).
4. `Builder`-typed public signatury `@deprecated` se shimem (odstranění 3.0).
5. Export přes `DataSource::get()`.
6. `analyse`/`lint` čisté; benchmark bez regrese.
7. Docs (`docs/table/data-sources.md`, `architecture/table.md`) + boost guidelines
   sync (stop hook vynucuje).
8. ADR 0019 → ACCEPTED; `v2-master-plan.md` V2.0 exit odškrtnut, V2.1 dostane
   poznámku o koordinaci s V2.0.b.
