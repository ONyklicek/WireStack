# V2.4 — ERP-safe execution invarianty: implementační plán

Rozpracování fáze **V2.4** z [`v2-master-plan.md`](v2-master-plan.md). Čtyři
z velké části **nezávislé** produktové balíky nad čistou základnou (V2.0–V2.3),
které naplňují ADR 0017 invariant G (authorization/scope/tenancy/audit first-class).

## 0. Stav (ověřeno 2026-07-06)

Bez korekce „hotových" položek — vše otevřené, ale s hotovými podklady:

| Balík | Stav | Hotový podklad |
|---|---|---|
| **T Multi-tenancy** | 0 v src | **seam připraven** — `PluginManager` hook priorita, komentář `-100: security/scope (multi-tenancy)` (`PluginManager:222`); + `DataSource` z V2.0 jako attach point |
| **WF Workflow** | 0 v src | ADR 0018 navržený; enum kontrakty `Enum\HasColor/HasLabel/HasIcon` + `BadgeColumn` hotové; **`StatusColumn` rendering typ vzniká v V2.1 B-2** |
| **Q Queue** | 0 v src (reálně chybí) | Laravel queue; existující `TableExport`/`BulkAction`/`ImportAction` jako cíle |
| **N DB notifikace** | jen transient | `Notification`/`NotificationManager` + driver pattern (`SessionDriver`/`LivewireEventDriver`) → přidat `DatabaseDriver` + persist + bell |

**Závislosti:** T těží z V2.0 (scope na `DataSource` → drží pro každý zdroj);
WF `TransitionAction` konzumuje `RecordContract` (V2.0) a `StatusColumn` (V2.1 B-2);
Q/N jsou volnější. Fáze sedí **po V2.3**, ale balíky jsou paralelizovatelné.

## T — Multi-tenancy first-class (ADR 0017 invariant G) 🔴 bezpečnostně citlivé

### Cíl
Tenant scope jako **systémový invariant**, ne ruční `where('tenant_id', …)`.
Musí držet na read i write cestě a být **fail-safe**.

### Práce
| Krok | Soubor | Změna |
|---|---|---|
| T-1 | `core/src/Tenancy/TenantScope.php` + `Contracts/TenantResolver.php` | resolve aktuálního tenanta (app-provided); default `null` |
| T-2 | `core/src/Tenancy/TenancyPlugin.php` | registruje `table.querying` hook na **priority -100** (běží první, před vším) → scopne `DataSource`/query na tenanta |
| T-3 | write cesta: `SaveHandler` + `BulkAction` | při create doplnit tenant klíč; při update/delete ověřit tenant ownership (přes policy/scope, ne callback) |
| T-4 | `DataSource` (V2.0) | scope se aplikuje **na source** (ADR 0019 boundary invariant #2) → drží pro Eloquent i non-Eloquent |

### 🔴 Fail-safe default
Když je tenancy **zapnutá** a resolver nevrátí tenanta → **nic neprojde**
(prázdný výsledek / výjimka), **ne** „vše". Opt-in přes config; jednou zapnutá je
striktní. Toto je nejdůležitější bezpečnostní rozhodnutí celého V2.4.

### Testy
Scope aplikován na query i mutaci; cross-tenant přístup zamítnut; **fail-safe**
(resolver=null → 0 řádků, ne leak); interakce s existující authorization.

## WF — Workflow / state machine (impl ADR 0018)

### Cíl
Guarded, audited přechody stavů. Package = transition **seam**, ne workflow engine.

### Práce (dle ADR 0018)
| Krok | Soubor | Změna |
|---|---|---|
| WF-1 | `core/src/Workflow/WorkflowState.php` | deklarativní allowed-transition mapa (`allow($from,$to)`), `column()`, guard (`guard($to, fn($record,$user))`), `after($to, fn)` hooks; `canTransition($record,$to,$user): bool` |
| WF-2 | `core/src/Workflow/Exceptions/IllegalTransitionException.php` | ilegální přechod hlasitě |
| WF-3 | `core/src/Actions/TransitionAction.php` | extends `BaseAction`; nabídne se jen pro aktuálně povolené přechody (`HasAuthorization` + `canTransition`); přes `ActionPipeline`; audit entry; opt-in optimistic locking (N2) |
| WF-4 | **`StatusColumn` wiring** | rendering typ vzniká v **V2.1 B-2** (extends `BadgeColumn`, enum barva/ikona); V2.4 ho jen napojí na `WorkflowState` (aktuální stav + dostupné přechody) |
| WF-5 | Bulk varianta | `TransitionAction` bulk přes existující `BulkAction` cestu |

### Koordinace s V2.1
`StatusColumn` (samotný sloupec) = **V2.1 B-2**. V2.4 dodává **transition engine**
(`WorkflowState`/`TransitionAction`) + napojení. Nedělat `StatusColumn` dvakrát.

### Delegation boundary (ADR 0018)
Žádné BPMN/approval-org/scheduler. Přechody mutují přes existující save; dlouhé
`after()` hooky → V2.4 Q (queue). Enum status staví na canonical enum kontraktech.

### Testy
Legal/illegal transition; guard veto → žádná mutace + notifikace; audit entry
vzniká; concurrent transition → optimistic lock (race); povolené přechody dle usera.

## Q — Queued/background operace (v1-gaps #5)

### Cíl
Bezpečná async cesta pro dlouhé bulk akce / velké exporty/importy + notifikace po
dokončení.

### Práce
| Krok | Soubor | Změna |
|---|---|---|
| Q-1 | `core/src/Actions/Concerns/Queueable.php` | `->queue()` / `->queueOn($connection)` na akci; při běhu dispatchne job místo sync run |
| Q-2 | `core/src/Actions/Jobs/RunActionJob.php` (`ShouldQueue`) | serializovatelný action context → spustí `ActionPipeline` v jobu |
| Q-3 | `table/src/Export/` + `Import/` | `ExportAction`/`ImportAction` opt-in `->queue()`; velký dataset streamuje v jobu (chunk) |
| Q-4 | completion notifikace | po dokončení jobu → **N (DB notifikace)** „export hotov / X řádků importováno" (link na soubor) |

### Coordinace
Q-4 závisí na **N** (persistent notifikace přežije request/job boundary). Dělat Q
po N, nebo aspoň N-model napřed.

### Testy
Queueable akce dispatchne job (fake queue); job spustí pipeline; velký export
v jobu; completion notifikace vznikne; serializace contextu (žádné closury/Model
leak → `RecordContract` klíče).

## N — DB notification center (ddd-roadmap V2-6; odloženo z 1.x)

### Cíl
Persistent notifikace (přežijí request) + bell/center UI. Staví na existující
notification abstrakci (jen nový driver + model).

### Práce
| Krok | Soubor | Změna |
|---|---|---|
| N-1 | `core/src/Notifications/Drivers/DatabaseDriver.php` | nový driver (mirror `SessionDriver`) — zapíše do `notifications` tabulky |
| N-2 | `core/src/Notifications/DatabaseNotification.php` + migrace | Eloquent model (Laravel `notifications` schema kompat.: type/data/read_at/notifiable) |
| N-3 | `core/src/Notifications/NotificationCenter.php` + Blade bell | unread count, seznam, `markAsRead`/`markAllRead`; Livewire komponenta (jako `RelationManager` vzor) |
| N-4 | `NotificationManager` | volba driveru (session/livewire/**database**) přes config; multi-driver (toast + persist zároveň) |

### Testy
DatabaseDriver zapíše; center čte unread/read; markAsRead; multi-driver (toast +
DB současně); config přepínání driveru.

## Roadmap (balíky paralelní; interní pořadí)

| Balík | Obsah | Závislost | Riziko | Odhad |
|---|---|---|---|---|
| **T** | tenancy scope (hook -100 + DataSource) | V2.0 (attach na source) | **vysoké (security)** | 4–5 d |
| **WF** | WorkflowState + TransitionAction | ADR 0018; StatusColumn z V2.1 | střední | 4–5 d |
| **N** | DatabaseDriver + center/bell | — | nízké | 3–4 d |
| **Q** | Queueable action/export + completion | **N** (Q-4) | střední | 4 d |

**Celkem ~15–18 dní.** T/WF/N paralelizovatelné; **Q po N**. Doporučené interní
pořadí: **N → Q**, **T** a **WF** kdykoli paralelně.

### Milníky
```
        ┌─ T: tenant scope fail-safe na query i mutaci ──────────┐
V2.3 ───┼─ WF: legal/guarded transition + audit ────────────────┼─► V2.4 DONE
        ├─ N: DB notifikace + bell/center ──► Q: queued ops ─────┘
        └─                                    + completion notif
```
- **T = nejrizikovější milník** (bezpečnost): go/no-go = **fail-safe test**
  (resolver=null → 0 řádků, žádný leak). Bez něj tenancy nezapínat.
- **N před Q** (completion notif potřebuje persist).
- **WF navazuje na V2.1 StatusColumn** — koordinovat, ať sloupec vznikne jen jednou.

## Testovací strategie

- **T (security-first):** cross-tenant leak testy = povinné; fail-safe default;
  scope na read (DataSource) i write (SaveHandler/Bulk); interakce s authorization.
- **WF:** stavový automat shape coverage (legal/illegal/guard-veto/concurrent);
  audit + optimistic lock integrace.
- **Q:** `Queue::fake()`, job spustí pipeline, serializace bez Model/closure leaku.
- **N:** driver zápis, center read-state, multi-driver.
- **Matrix:** `composer test:core` (T/WF/N/Q owner) + `test:table` (StatusColumn,
  export/import queue) + `test:forms` (SaveHandler tenant scope); `Integration`
  (hook -100 scope, action queue dispatch, notification persist); `analyse`+`lint`.

## Rizika & mitigace

| Riziko | Mitigace |
|---|---|
| **Tenant leak** (nejhorší třída) | fail-safe default (scope chybí → nic); scope na `DataSource` (drží pro všechny zdroje); povinné cross-tenant testy |
| WF/StatusColumn dvojí práce s V2.1 | `StatusColumn` = V2.1 B-2; V2.4 jen engine + wiring |
| Q serializace (Model/closure v jobu) | context přes `RecordContract` klíče (V2.0), ne Model; job resolvne record znovu |
| Concurrent transition data race | `TransitionAction` respektuje optimistic locking (N2) |
| N migrace koliduje s app `notifications` | Laravel-kompat. schema; config `table_name`; ne hard override |
| Scope creep (workflow engine / panel) | delegation boundary ADR 0018; Q bez vlastního scheduleru (Laravel queue) |

## Definition of done

1. **Tenancy** opt-in, fail-safe, vynucená na read (DataSource) i write; cross-tenant
   leak testy zelené — **bez fail-safe testu tenancy neshipovat**.
2. **Workflow:** `WorkflowState` + `TransitionAction` (guarded/audited/lock-safe);
   `StatusColumn` (z V2.1) napojený na aktuální stav + přechody.
3. **Queue:** akce/export/import opt-in `->queue()`; completion → DB notifikace;
   serializace bez leaku.
4. **DB notifikace:** `DatabaseDriver` + persistent model + bell/center; multi-driver.
5. Vše plně otestované (100% nového; security shape coverage u T); `analyse`/`lint`
   čisté; bez perf regrese.
6. Docs (tenancy/workflow/queue/notifications) + boost guidelines sync.
7. `v2-master-plan.md` V2.4 exit odškrtnut; ADR 0018 → ACCEPTED (impl hotová).
